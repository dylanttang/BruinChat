# Group DMs Plan (Issue #116)

**Goal:** People can start a group chat with classmates (up to 20 people), name it or leave it unnamed, add classmates, rename it and leave it. The server enforces who can be added.

**Approach:** Build for the final product, not the quickest version. Every chat gets an explicit kind (class, direct, group, team) instead of guessing from `isGroup` and `course`. Membership changes show as notices in the chat ("Rex added Ana"). Existing class chats, DMs and the team chat must keep working; check each after the kind change.

**Status:** Planning. Server first, while Eusern builds the classmate picker (#82). UI waits on design review.

## Decisions (Rex, 2026-11-24)

- **Chat kind:** add an explicit `kind` to every chat (`class`, `direct`, `group`, `team`), backfilled once for existing chats. Code stops inferring kind from `isGroup` and `course`. #117 (Classes and DMs on one screen) relies on this.
- **Who can be added:** only people who share a class chat with the person adding them, with no block in either direction between the two, and not banned or deleted. Checked on the server on create and on add; never trust the list the app sends.
- **Shared-class check:** one server helper, shared with Eusern's classmates endpoint (#82). Agree with Eusern who writes it.
- **Blocks inside a group:** two members who blocked each other both stay. Each just doesn't see the other's messages and gets no pushes from them (how class chats already work). Adding is refused only when the adder and the person added have a block between them, so the group never reveals who blocked whom.
- **After the quarter:** members stay in the group even when they no longer share a class. The class rule applies only at the moment someone is added.
- **Same people twice:** picking one person reopens the existing DM. Picking several always creates a new group.
- **Name:** optional. With no name, the title is built from members' names ("Ana, Ben and 3 others"). Anyone in the group can rename it or clear the name.
- **Notices:** a system message type for "X created the group", "X added Y", "X renamed the group to …", "X left". Shown centered in the chat, not as a bubble. Notices don't count as unread messages and don't send pushes.
- **Spam limits:** at most 20 members per group, about 10 new groups per person per day, plus a rate limit on adds. Getting added sends a push.
- **Permissions:** anyone in the group can add, rename and leave. Store the creator so admin roles can be added later without a migration.
- **Leaving:** group DMs get "Leave group" in chat info. The last person leaving deletes the group and its messages. They can also be archived like DMs.

## Done when

- [ ] Create a group of three or more; everyone sees it in their list and gets messages live and as pushes
- [ ] Add people, rename (and clear the name), and leave, each with a notice in the chat
- [ ] Can't add someone you don't share a class with, someone with a block either way, or a banned or deleted account, even by calling the API directly (tests)
- [ ] Member cap and daily group limit enforced (tests)
- [ ] Existing class chats, DMs and the team chat still list, open, send, notify, archive and leave as before
- [ ] `npm test`, `npx tsc --noEmit` and `npm run test:security` pass

## Steps

### Server
1. [ ] Add `kind` to `models/Chat.js`; backfill script for existing chats (course → class, `isGroup: false` → direct, others → team). Set `kind` everywhere chats are created (class enrollment, DMs, seed).
2. [ ] Switch server code from `isGroup`/`course` checks to `kind` (chat list `?kind=` filter, leave route, push titles, direct recipient check). Keep `?kind=group` returning class and team chats so the current app keeps working until #117.
3. [ ] Make `name` optional for group DMs.
4. [ ] Shared-class + block + banned/deleted check helper (coordinate with #82).
5. [ ] `POST /api/chats/group` (create, 2 to 19 others, optional name, daily limit).
6. [ ] `POST /api/chats/:id/members` (add), `PATCH /api/chats/:id` (rename). Leave reuses `DELETE /:id/members/me`; fix its empty-chat delete, which never runs today.
7. [ ] System notice messages: model field, created on create/add/rename/leave, excluded from unread and pushes.
8. [ ] Push to people when they're added.
9. [ ] Tests for all of the above, including direct API calls with bad member lists.
